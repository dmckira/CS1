01 Arquitectura del laboratorio

El laboratorio usa tres contenedores Docker que se comunican entre sí a través de una red interna llamada calidad-net. Desde tu máquina accedes a Jenkins y SonarQube por localhost, pero entre contenedores se comunican por nombre.

Todos los contenedores viven en la red calidad-net. Jenkins llega a SonarQube por http://sonarqube:9000.

Jenkins

  • Puerto agentes: 50000
  • Datos en: jenkins_home/
  • Incluye: Python 3, pip, sonar-scanner

SonarQube

Requisito previo: Docker Desktop debe estar corriendo en tu máquina antes de ejecutar cualquier comando de esta guía. En Mac aparece en la barra de menú superior; en Windows en la bandeja del sistema.

02 Los Dockerfiles del proyecto

El proyecto tiene dos Dockerfiles, uno por servicio. Están en sus propias carpetas dentro del repositorio.

CS1/
  ├── jenkins/
  │   └── Dockerfile    # imagen de Jenkins con Python + sonar-scanner
  ├── sonarqube/
  │   └── Dockerfile    # imagen de SonarQube Developer
  └── Jenkinsfile      # pipeline declarativo de CI/CD

Dockerfile de Jenkins

La imagen base jenkins/jenkins:2.555.1-lts solo trae Jenkins y Java. Necesitamos agregarle Python, pip y sonar-scanner porque el pipeline los necesita para correr las pruebas y analizar el código.

Dockerfile jenkins/Dockerfile 
FROM jenkins/jenkins:2.555.1-lts

# Cambiamos a root para poder instalar paquetes del sistema
USER root

# Instalamos Python3, pip y herramientas de descarga
RUN apt-get update && apt-get install -y \
    python3 \
    python3-pip \
    python3-venv \
    unzip \
    curl \
    && rm -rf /var/lib/apt/lists/*

# Debian 13 bloquea pip de forma global por defecto.
# Esta variable lo habilita dentro del contenedor (es seguro hacerlo aquí).
ENV PIP_BREAK_SYSTEM_PACKAGES=1

# Descargamos e instalamos sonar-scanner CLI
RUN curl -sSLo /tmp/sonar-scanner.zip \
    https://binaries.sonarsource.com/Distribution/sonar-scanner-cli/sonar-scanner-cli-6.2.1.4610-linux-x64.zip \
    && unzip /tmp/sonar-scanner.zip -d /opt \
    && mv /opt/sonar-scanner-6.2.1.4610-linux-x64 /opt/sonar-scanner \
    && ln -s /opt/sonar-scanner/bin/sonar-scanner /usr/local/bin/sonar-scanner \
    && rm /tmp/sonar-scanner.zip

# Volvemos al usuario jenkins por seguridad
USER jenkins

EXPOSE 8080
EXPOSE 50000

03 Red Docker y volúmenes persistentes

Crear la red compartida

La red calidad-net permite que Jenkins y SonarQube se comuniquen por nombre de contenedor. Solo necesitas crearla una vez.

docker network create calidad-net

Para verificar que existe:

docker network ls

¿Por qué usar un volumen?

Sin volumen, cada vez que el contenedor se reinicia o se borra, pierdes toda la configuración: plugins instalados, jobs creados, credenciales, historial de builds. Con un volumen, esos datos se guardan en una carpeta de tu máquina y el contenedor los lee al arrancar.

Sin volumen

  • Datos dentro del contenedor
  • docker rm jenkins → todo perdido
  • Reconfigurar desde cero cada vez

Con volumen

  • Datos en tu máquina local
  • docker rm jenkins → datos intactos
  • Al recrear el contenedor, todo vuelve

Tipo de volumen: bind mount

Usamos un bind mount: una carpeta real de tu sistema de archivos mapeada al contenedor. La carpeta jenkins_home/ vive dentro de la carpeta jenkins/ del proyecto.

Mac / Linux
Windows

La carpeta se crea automáticamente al primer arranque. Si quieres crearla manualmente:

mkdir -p /ruta/al/proyecto/CS1/jenkins/jenkins_home

Si Jenkins no puede escribir en la carpeta, arregla los permisos:

sudo chown -R 1000:1000 ./jenkins/jenkins_home

La carpeta se crea automáticamente. Para crearla manualmente desde CMD:

mkdir C:\ruta\al\proyecto\CS1\jenkins\jenkins_home

En Windows, Docker Desktop necesita permiso de acceso a la unidad. Ve a Settings → Resources → File sharing y agrega la unidad C: si no está.

Para empezar de cero (borrar toda la configuración de Jenkins): borra el contenedor y luego elimina la carpeta jenkins_home/. Al recrear el contenedor, Jenkins arranca como nuevo.

05 Configurar Jenkins para el repositorio de GitHub

Jenkins necesita 4 configuraciones para poder leer el Jenkinsfile del repositorio github.com/duvanfr/CS1 y ejecutar el pipeline.

1

Primer acceso — contraseña inicial

Abre http://localhost:8080. Jenkins pedirá una contraseña de desbloqueo. Obtenla con:

docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword

Pega el resultado en la pantalla de desbloqueo. Luego selecciona Install suggested plugins y crea el usuario administrador.

2

Instalar plugins adicionales

Ve a Manage Jenkins → Plugins → Available plugins e instala:

SonarQube Scanner HTML Publisher Timestamper

Los plugins Pipeline, Git y JUnit vienen con los plugins sugeridos del paso anterior. Reinicia Jenkins al terminar.

3

Crear credenciales de GitHub

Ve a Manage Jenkins → Credentials → System → Global credentials → Add Credentials:

KindUsername with password
Usernameduvanfr (tu usuario de GitHub)
PasswordPersonal Access Token de GitHub (ver abajo)
IDgithub-credentials
Cómo crear el Personal Access Token en GitHub: Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → marca el scope repo → Generate. Copia el token — solo se muestra una vez.

Crear el job Pipeline

07 Errores comunes y soluciones

Error: network calidad-net not found

Error al ejecutar docker run
docker: Error response from daemon: failed to set up container networking: network calidad-net not found

Causa: La red Docker no existe todavía.

Solución: Crea la red antes de levantar los contenedores.

docker network create calidad-net

Error: container name already in use

Error al ejecutar docker run
docker: Error response from daemon: Conflict. The container name "/jenkins" is already in use...

Causa: Ya existe un contenedor con ese nombre, aunque esté detenido.

Solución: Elimina el contenedor viejo y vuelve a correrlo.

docker rm jenkins
docker run -d --name jenkins ...   # tu comando completo

Error: permission denied en ~/.docker/buildx (Mac)

Error al ejecutar docker build
ERROR: failed to build: stat /Users/usuario/.docker/buildx/refs/...: permission denied

Causa: Docker BuildKit tiene un problema de permisos en Mac con Docker Desktop.

Solución: Desactiva BuildKit con la variable de entorno.

DOCKER_BUILDKIT=0 docker build -t mi-jenkins ./jenkins/.

Error: python3 not found (en el pipeline)

Stage 2 del pipeline — Jenkins Console Output
+ python3 --version
/var/jenkins_home/workspace/.../script.sh: python3: not found

Causa: La imagen de Jenkins no tiene Python instalado. Ocurre si usas la imagen base sin las modificaciones del Dockerfile de este proyecto.

Solución: Asegúrate de estar usando el Dockerfile de la carpeta jenkins/ que instala Python en el RUN apt-get install. Si reconstruiste la imagen sin ese paso, vuelve a construir con el Dockerfile correcto.

DOCKER_BUILDKIT=0 docker build -t mi-jenkins ./jenkins/.

Error: externally-managed-environment (pip)

Stage 2 del pipeline — Jenkins Console Output
error: externally-managed-environment

× This environment is externally managed
╰─> To install Python packages system-wide, try apt install python3-xyz...

Causa: Debian 13 (Trixie) bloquea la instalación global de paquetes pip por defecto para proteger los paquetes del sistema.

Solución: El Dockerfile del proyecto incluye ENV PIP_BREAK_SYSTEM_PACKAGES=1. Si ves este error, la imagen fue construida sin esa línea. Verifica el Dockerfile y reconstruye.

# En el Dockerfile de jenkins/ debe existir esta línea:
ENV PIP_BREAK_SYSTEM_PACKAGES=1

# Luego reconstruye la imagen
docker stop jenkins && docker rm jenkins
DOCKER_BUILDKIT=0 docker build -t mi-jenkins ./jenkins/.
docker run -d --name jenkins --network calidad-net \
  -p 8080:8080 -p 50000:50000 \
  -v /ruta/CS1/jenkins/jenkins_home:/var/jenkins_home \
  mi-jenkins

SonarQube no carga en localhost:9000

Causa: SonarQube tarda aproximadamente 1 minuto en inicializar Elasticsearch internamente.

Solución: Espera y recarga. Puedes monitorear el inicio con:

docker logs -f sonarqube

Cuando veas la línea SonarQube is operational en los logs, ya puedes acceder al navegador.
